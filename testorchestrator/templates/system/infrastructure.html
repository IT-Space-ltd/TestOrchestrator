Workers

A worker is the execution process or destination — the machine that runs tests. Runtime connections (below) are the KRE installations used on a worker.

Remote worker installs: the bundled installer asks for the controller Buildbot PB endpoint — this host's name/IP + port 9989, not the https portal URL. Candidates on this controller:{% if pb_hints %}{% for h in pb_hints %} {{ h }}:9989{% if not loop.last %} {% endif %}{% endfor %}{% else %} <controller-host>:9989{% endif %} — pick the one reachable from the worker host. Worker name + one-time password come from the target record — create the target first, then Issue password under Manage ▾ if the flash banner was missed.

Connection requirements per target type
TargetWhat must be reachable and configured
Windows or Linux Buildbot worker The registered worker must be able to connect to the configured Buildbot master address and port (PB, default 9989). Its service account must be able to read the project, launch Node.js and the browser, and write results.
Agentless Linux SSH The controller-side dispatcher must be able to reach the configured SSH host and port. The administrator must configure the SSH username and credential, approve the host fingerprint, and have working SFTP and a writable remote workspace. The SSH account must be able to launch Node.js and the browser.

Target connectivity and application reachability are different checks: an online worker or successful SSH connection does not mean the browser on that machine can reach the application under test. If the target fetches the repository or dependencies itself, it also needs access to the relevant repository or package registry.

Remote worker installers

A remote host runs the bundled Buildbot worker — download the offline package for its platform, run it on the remote machine, and enter the controller address, workername, and per-worker password shown when the target was added. The worker connects outbound to the controller — no inbound port on the remote host.
