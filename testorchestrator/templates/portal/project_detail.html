Results & Artifacts — durable storage

Primary storage keeps your results and files available after the worker is removed. Execution metadata, parsed results, and artifact references live in the database; file bytes go to the project's active destination. New destinations apply to new executions — historical artifacts keep their original store reference and stay retrievable. Staged workspace copies are cleanup-eligible only after a stored copy verifies.

Git publication is optional and does not replace primary storage — a publication failure does not mean the tests failed. Per-execution publication status is shown separately on each execution.

Artifact capture

These are collection permissions — they control which generated files TestOrchestrator transfers and retains. They do not guarantee a framework will produce those files, and they do not prevent a framework from generating them on the worker (generation is a framework setting). The policy is snapshotted into each execution; changing it affects new runs only. Excluded files stay recorded in the evidence manifest. Broad checkout-directory uploads remain prohibited.

Optional — Git publication

Publishing copies explicitly selected reports to a Git repository. It is optional, independent of primary storage, and never implies test success or failure. Source changes, snapshots, environment exports, and raw sensitive API traffic are excluded by default. Publication status is shown per execution, separately from durable storage.
